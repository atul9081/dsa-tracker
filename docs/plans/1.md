## Phase 3 — Supabase SQL Schema

Run this in **Supabase → SQL Editor → New Query**:

```sql
CREATE TABLE problems (
  id               INTEGER PRIMARY KEY,
  title            TEXT NOT NULL,
  title_slug       TEXT NOT NULL UNIQUE,
  difficulty       TEXT NOT NULL CHECK (difficulty IN ('EASY', 'MEDIUM', 'HARD')),
  topic_tags       TEXT[] NOT NULL,
  description      TEXT,          -- scraped from leetcode.ca (HTML, nullable)
  ac_rate          FLOAT,
  paid_only        BOOLEAN DEFAULT FALSE,
  olt_score        INTEGER DEFAULT 0,
  created_at       TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_problems_difficulty ON problems(difficulty);
CREATE INDEX idx_problems_topic_tags ON problems USING GIN(topic_tags);

CREATE TABLE user_progress (
  problem_id  INTEGER PRIMARY KEY REFERENCES problems(id) ON DELETE CASCADE,
  status      TEXT NOT NULL DEFAULT 'TO_DO'
              CHECK (status IN ('TO_DO', 'ATTEMPTED', 'DEBUGGING', 'SOLVED')),
  updated_at  TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE daily_queues (
  date         DATE PRIMARY KEY,
  problem_ids  INTEGER[] NOT NULL,
  generated_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE VIEW problems_with_status AS
  SELECT p.*, COALESCE(up.status, 'TO_DO') AS status, up.updated_at AS status_updated_at
  FROM problems p
  LEFT JOIN user_progress up ON p.id = up.problem_id;
```

## Phase 5 — Seed Script (`scripts/seed.ts`)

**Sources:**
- Metadata: `data/1.json` through `data/8.json` + `json-data.json` (skip `json-data-2.json`)
- Descriptions: `https://leetcode.ca/all/{questionFrontendId}.html` → parse `<div class="markdown-body">`

**Algorithm:**
1. Read all local JSON files → deduplicate by `questionFrontendId`
2. Filter: `paidOnly === false` AND `topicTags` doesn't include `database`
3. Compute `olt_score` = max TOPIC_SCORE_MAP value across problem's topic slugs
4. For each problem, fetch `https://leetcode.ca/all/{id}.html`, extract `<div class="markdown-body div-width">` content → store as HTML string
5. If fetch fails → set `description = null` (graceful fallback)
6. Upsert to `problems` table in batches of 20
7. Seed `user_progress` from JSON status fields (SOLVED/ATTEMPTED → insert rows)

**Rate limiting:** 200ms delay between leetcode.ca fetches.

## Phase 7 — API Routes

### `GET /api/queue` — Get today's queue
1. Read today's date (IST = UTC+5:30)
2. Query `daily_queues WHERE date = today`
3. If found: return problems with status joined
4. If not: run queue generation algorithm → insert → return

### Queue Generation Algorithm
```
1. FILTER: status ≠ SOLVED AND paid_only = false
2. SCORE: weight = olt_score^2 × difficultyMultiplier[difficulty]
3. SPLIT into HARD[], MEDIUM[], EASY[] buckets
4. WEIGHTED RANDOM SAMPLE without replacement:
   - 2 from HARD, 2 from MEDIUM (fallback to next difficulty if exhausted)
5. SHUFFLE the 4 cards (hide position-based difficulty hints)
6. INSERT into daily_queues
7. RETURN problems
```

### `POST /api/queue` — Force regenerate (body: `{ date?: string }`)

### `POST /api/progress` — Update status
```
Body: { problem_id: number, status: Status }
→ Upsert into user_progress
→ Return { ok: true }
```
